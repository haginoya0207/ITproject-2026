1. 文書概要・目的1.1. 本書の目的本書は、01_request.md（AI質問機能 追加要望書）に基づき、既存の Express / TypeScript 製 Web アプリケーションに追加する「AI質問機能」の機能要件、入力制約、例外処理、および非機能要件を定義する。次フェーズである詳細設計（03_design.md）および実装（04_implementation.md）のインプットとすることを目的とする。1.2. 対象システム・技術前提バックエンド: Node.js / Express / TypeScriptテンプレートエンジン: EJS（views/ai/index.ejs）フロントエンド: Vanilla JavaScript（public/ai/ai.js）利用 AI / SDK: Google Gemini API / @google/genai（標準モデル: gemini-2.5-flash）環境変数管理: dotenv（APIキーは AI_API_KEY から取得）2. システムスコープ・基本方針項目確定仕様備考・採用理由画面構成独立画面（GET /ai）として提供既存 TODO 画面との責務分離を明確化（必要に応じて共通ヘッダー等から導線を設置）対話形式1問1答のステートレス形式会話履歴の永続化を行わず、既存の DB スキーマやセッション管理への影響をゼロにする通信方式非同期 JSON API（POST /ai/ask）ページ遷移なしで質問送信・回答描画を行い、既存コントローラー設計と統一する回答描画クライアント側で整形＋サニタイズ描画AI 出力の可読性を確保しつつ、XSS 脆弱性を防止する入力・応答制限最大 2,000 文字 / タイムアウト 30 秒過度なトークン消費とサーバーリソース占有を防止する3. 機能要件FR-01: AI質問画面の表示（GET /ai）ユーザーがブラウザで /ai にアクセスした際、EJS テンプレート（views/ai/index.ejs）をレンダリングして質問画面を返却する。画面には以下の UI 要素を配置する。質問入力エリア: 複数行テキスト入力欄（textarea）および現在の入力文字数カウンター（例: 0 / 2000）送信ボタン: 質問を送信するアクションボタンローディング表示領域: AI 応答待機中であることを示すインジケーター（初期状態は非表示）回答表示領域: AI から返却された回答テキストを表示するエリア（初期状態は非表示またはプレースホルダー）エラー表示領域: バリデーションエラーや通信エラーをユーザーに通知するエリア（初期状態は非表示）ナビゲーション導線: 既存の TOP 画面・TODO 画面へ戻るリンクFR-02: 質問送信・AI応答生成（POST /ai/ask）フロントエンドから JSON 形式（{ "question": "..." }）で送信された質問リクエストを受け付ける。コントローラー層（aiController.ts）で入力バリデーションを実施し、不正な場合は 400 Bad Request を返却する。サービス層（aiService.ts）で @google/genai SDK を初期化（apiKey: process.env.AI_API_KEY）し、Gemini API を呼び出して回答テキストを生成する。生成された回答を JSON 形式（200 OK）でフロントエンドへ返却する。FR-03: 回答の表示・サニタイズ処理フロントエンド（public/ai/ai.js）は POST /ai/ask の成功レスポンスを受信後、ローディング表示を解除し、回答表示領域に結果を描画する。AI の回答に含まれる改行や見出し・箇条書き等を読みやすく整形して表示する。セキュリティ要件: AI が生成した文字列に HTML タグやスクリプトが含まれる場合でも実行されないよう、DOM 挿入前に必ず HTML エスケープまたはサニタイズ処理を行う。FR-04: クライアント側入力補助・多重送信防止送信ボタン押下時、フロントエンド側でも空文字チェックおよび文字数上限（2,000文字）チェックを行い、違反時は API リクエストを送らずにエラーメッセージを表示する。API リクエスト送信開始からレスポンス受信（成功または失敗）完了までの間、送信ボタンおよび入力欄を非活性（disabled）にし、二重送信を防止する。再質問を行った場合、前回のエラー表示はクリアし、新しい回答で表示領域を更新する。4. 入力制約・バリデーション仕様4.1. リクエストパラメータ制約（POST /ai/ask）項目名型必須制約条件エラー時の挙動questionstring必須・文字列型であること・前後空白除去（trim()）後、1文字以上であること・文字数が 2,000文字以下であることHTTP 400 Bad Request とユーザー向けエラーメッセージを返却4.2. バリデーションエラーメッセージ基準未入力・空白のみの場合: 「質問内容を入力してください。」2,000文字超過の場合: 「質問は2,000文字以内で入力してください。」不正なデータ形式の場合: 「リクエスト形式が正しくありません。」5. 例外・エラーハンドリング要件サーバーの異常終了（クラッシュ）を防ぎ、すべての異常系で一貫した JSON エラーレスポンスまたはグローバルエラーハンドラー連携を行う。エラー種別発生条件HTTP ステータス画面表示メッセージ（例）バックエンド処理入力値不正空文字、2,000文字超過、型不正400「質問は2,000文字以内で入力してください。」等コントローラーで検知し即座に JSON 返却環境設定不備AI_API_KEY 未設定・空文字500「現在AI機能を利用できません。管理者にお問い合わせください。」サーバーログに詳細を出力し、キー情報は露出しないAPI タイムアウトGemini API の応答が 30秒を超過504（または 500）「AIからの応答がタイムアウトしました。時間をおいて再度お試しください。」AbortController 等で処理を中断しエラーログ出力外部API通信エラーGemini API 側の障害、レート制限（429）、認証エラー502（または 500）「AIサービスとの通信中にエラーが発生しました。しばらくしてから再度お試しください。」SDK 例外をキャッチし、ステータスに応じたログ出力予期せぬ例外上記以外のランタイムエラー500「予期せぬエラーが発生しました。」next(error) で既存のグローバルエラーハンドラーへ委譲6. 非機能要件NFR-01: アーキテクチャ・保守性既存の TODO アプリ（src/apps/todo/）のディレクトリ構成および責務分離を踏襲する。src/apps/ai/aiRouter.ts: ルーティング定義のみを担当src/apps/ai/aiController.ts: HTTP リクエストのパース、バリデーション、レスポンス返却を担当src/apps/ai/aiService.ts: @google/genai を用いた Gemini API 呼び出し・タイムアウト制御を担当（Express の req/res に依存させない）NFR-02: セキュリティAPIキー保護: AI_API_KEY はサーバー側の .env のみで管理し、フロントエンドの JS や HTML テンプレート、エラーレスポンスに一切出力しない。XSS 対策: AI の応答文字列は信頼できない外部入力として扱い、サニタイズなしで innerHTML に直接代入しない。プロンプトインジェクション配慮: ユーザー入力は質問データとして独立して扱い、システム設定や環境変数へアクセスする権限を AI に与えない。NFR-03: パフォーマンス・可用性外部 API 呼び出しには 30秒のタイムアウト上限 を設け、長時間ハングアップするリクエストを遮断する。すべての I/O 処理は async / await による非同期処理で実装し、Node.js のイベントループをブロックしない。NFR-04: 既存機能への非影響index.ts へのルーター追加（app.use('/ai', aiRouter)）は、既存の /todo ルーティングより前、かつ 404 ハンドラー・エラーハンドラーより前に配置する。既存の TODO 機能、データベース接続、ミドルウェア設定には変更を加えない。7. エンドポイント・ファイル構成一覧7.1.
